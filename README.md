# TimeFlow

**让时间有迹可循，让计划与现实真正对得上。**

TimeFlow 是一款围绕 **时间记录、计划对照、结构分析与 AI 辅助管理** 构建的个人时间管理应用。它不只关心「今天做了多少事」，也希望帮助你看清：时间实际花在了哪里，哪些安排与预期存在偏差，以及下一步应该如何调整。

适合正在备考、长期学习、管理个人项目，或单纯希望更清楚地理解自己时间使用方式的人。

> **项目状态：v0.1 预览阶段。** 目前以 macOS 桌面端为主要使用入口，部分智能执行、iOS Capture 与同步能力仍在逐项验证。功能说明基于 2026-11-08 的项目审计，不代表每项实验功能都已具备正式产品级稳定性。

## TimeFlow 能做什么？

### 1. 记录真正发生的时间

- 按日期和时间段补登已完成的活动，管理活动名称、分类和标签。
- 在日时间轴中浏览记录，修改记录名称、时间与分类，或删除不再需要的记录。
- 将学习、休息、运动、娱乐等活动归入自己的时间结构。
- 在首页并排查看 **计划日程** 与 **实际记录**，减少「计划已经完成」和「实际已经发生」之间的混淆。

> 计划日程来自系统日历或导入的 ICS 文件；实际记录由 TimeFlow 管理。两者是不同的数据来源，导入日程不会自动生成实际用时。

### 2. 看懂自己的时间结构

- 按 **日、周、月、年** 查看各类时间的占比与变化。
- 通过分类、标签、趋势图和统计概览，发现时间分配的规律。
- 在「时间结构」页面切换 **记录 / 计划** 模式。
- 为指定日期的分类设置目标时长，直观看到 **昨日参考、今日实际与今日计划** 的对照。
- 自定义合计指标，例如把多个分类汇总为自己关心的「有效学习时间」。

时间结构的目的不是给每一分钟打分，而是用真实记录帮助你调整接下来的安排。

### 3. 建立适合自己的分类体系

- 创建、重命名、调整颜色和排序时间大类。
- 创建标签，并进行编辑、移动、排序或删除。
- 对已有记录重新分类，让统计结果跟随当前分类体系更新。
- 初次使用时，可通过个人方向引导建立基本分类。

记录、分类和标签相互关联；涉及批量移动或删除的操作应先确认影响范围并保留备份。

### 4. 用自然语言管理时间：DSH

TimeFlow 内置实验性的 **DSH 智能执行系统**。配置支持的模型服务后，你可以尝试直接描述任务，而不是只通过界面逐个操作。

例如：

> 帮我查一下昨天「英语阅读」的时间记录。
>
> 补登今天 14:00 到 15:00 的数学复习。
>
> 把刚才查到的那条记录改名为「线性代数练习」。

当前已有实测证据支持的代表性路径包括：**按范围查询记录、同日补登、修改单条记录标题、读取现有分类目录**。更多分类管理及批量操作已经接入能力目录，但仍需逐项完成真实产品链路的验收。

DSH 的设计原则是：

- **先理解，再操作**：先识别目标、查询现有数据与可用能力。
- **受控执行**：操作受到工具权限和参数约束，部分高影响操作需要明确确认。
- **写后核对**：尝试根据业务数据核验操作结果，而不只相信模型说「已完成」。
- **经验复用**：逐步积累经过验证的只读经验，并在合适条件下复用。

**注意：** DSH 不是可以任意操作系统的通用代理。目前 L1 经验检索与 L2/L3 Skill 机制仍属于实验功能；已验证的发布 Skill 以**只读流程**为主，不能把它理解为已经实现自主生成并稳定执行所有业务操作。

### 5. 管理、保存和导出数据

- 配置本地文件仓库时，时间记录及分类数据由基于 SQLite 的 Core 管理。
- 支持导出应用 JSON 备份和记录 Markdown 文件。
- 提供从应用备份合并导入的入口；重要数据恢复前建议先另存副本。
- 支持连接 macOS 系统日历，或导入 ICS 日程文件作为计划参考。
- 提供基于文件仓库的同步能力及可选 iCloud 仓库；跨设备冲突和恢复场景仍需进一步验证。

## 开始使用

1. 打开此 GitHub 仓库的 **Releases** 页面，查看是否提供与你的 macOS 设备兼容的 v0.1 安装文件。只有发布页实际附带安装包时才能直接下载安装。
2. 安装并打开 TimeFlow，完成首次个人方向和分类引导。
3. 按需创建或选择数据仓库；建议从开始使用时就保留备份。
4. 尝试补登几条真实记录，然后前往「时间结构」查看分类占比，切换计划模式设置今天的目标。
5. 如需 AI 辅助，在设置中填写模型连接信息并进行连接测试。**基本的手动记录和统计并不要求启用 AI。**

具体系统版本、芯片兼容性、安装包格式及签名状态，以对应 Release 的实际发布说明和附件为准；当前审计材料没有提供这些兼容性结论。

## 数据与隐私说明

TimeFlow 的时间记录可以保存在用户选择的本地仓库中；不同模式下也可能使用应用本地存储保存设置、会话与其他状态。选择 iCloud 仓库时，相关数据会进入所选云盘存储路径。

AI 是可选能力。启用模型连接后，为完成对话或执行任务，相关请求内容可能发送至你配置的模型服务提供方。**请根据该服务的隐私政策决定是否启用，以及输入哪些信息。**

目前审计所见的 API Key 保存方式是应用本地 Web 存储，而非可据此承诺的系统钥匙串加密存储；常规 JSON 备份导出会排除密钥。不要将 API Key、私人记录库或包含敏感数据的调试日志提交到公开仓库。

## 已知边界与后续方向

v0.1 优先让 **记录 → 观察 → 计划 → 调整** 的基本流程可用。以下工作仍在推进：

- 强化 DSH 的查询范围、跨日操作、批量写入与高影响操作保护。
- 提升分类变更、统计、AI 经验之间的一致性与可验证性。
- 完善 Skill 的适用条件、失败回退与独立评测，而不是仅凭模型自述判定其已学会。
- 继续验证 iOS Capture、文件同步、冲突恢复和安装分发体验。
- 补充更完整的使用指南、截图、自动化测试与问题反馈流程。

v0.1 的具体内容和审计基准下的注意事项见 [RELEASE_v0.1.md](RELEASE_v0.1.md)。
